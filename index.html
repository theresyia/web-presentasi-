01 · Latar Belakang

Deskripsi Masalah

Banyak orang melakukan transaksi harian — membeli makanan, membayar transportasi, menerima uang — namun jarang dicatat sehingga sulit mengetahui ke mana uang digunakan.

01

Sering lupa mencatat

Pengeluaran kecil seperti makanan atau minuman sering tidak dicatat.

02

Sulit tahu ke mana uang pergi

Tanpa catatan jelas, pengeluaran terbesar sulit diketahui.

03

Pencatatan manual

Dicatat di buku atau catatan HP yang kurang terorganisir.

04

Sulit menghitung sisa uang

Pengguna harus menghitung pemasukan dikurangi pengeluaran sendiri.

05

Tidak ada laporan sederhana

Sulit melihat total pemasukan dan pengeluaran harian atau bulanan.

02 · Solusi

Penyelesaian: Aplikasi DompetKu

DompetKu membantu pengguna mencatat dan memantau keuangan sehari-hari dalam satu aplikasi.

  1. 1

    Tombol “Tambah Transaksi”

    Mudah digunakan, mengatasi kebiasaan lupa mencatat.

  2. 2

    Kategori pengeluaran

    Pengguna tahu uangnya dipakai untuk apa saja.

  3. 3

    Riwayat tersimpan rapi

    Semua transaksi tersimpan di dalam aplikasi.

  4. 4

    Saldo otomatis

    Sistem menghitung sisa uang tanpa hitung manual.

  5. 5

    Ringkasan harian & bulanan

    Laporan sederhana pemasukan dan pengeluaran.

03 · Business Logic

Alur Utama Sistem

Pengguna mencatat transaksi → sistem memvalidasi → saldo diperbarui otomatis → laporan dapat dilihat.

1

Input Transaksi

Pilih pemasukan/pengeluaran; isi nominal, kategori, tanggal, catatan.

→
2

Validasi Data

Nominal harus valid dan data wajib terisi sebelum disimpan.

→
3

Simpan Transaksi

Disimpan sebagai riwayat agar pencatatan terorganisir.

→
4

Hitung Saldo

Saldo = total pemasukan − total pengeluaran.

→
5

Kategori & Laporan

Pengeluaran dikelompokkan; ringkasan harian & bulanan tampil.

Rumus saldo saldo = Σ pemasukan − Σ pengeluaran

06 · SRS

Kebutuhan Nonfungsional & Aturan Bisnis

Nonfungsional

  • Keamanan: kata sandi disimpan aman, akses dibatasi per akun.
  • Privasi: data keuangan tidak terlihat pengguna lain.
  • Usability: navigasi konsisten lewat menu samping.
  • Responsif: nyaman di desktop & menyesuaikan perangkat.
  • Maintainability: modul transaksi, kategori, laporan, profil terpisah.
  • Reliability: data tersimpan tampil konsisten di dashboard & laporan.

Aturan Bisnis

  • Transaksi: Pemasukan atau Pengeluaran.
  • Setiap transaksi punya kategori dan nominal.
  • Kategori juga dibedakan jenis pemasukan/pengeluaran.
  • Saldo dihitung dari pemasukan dan pengeluaran.
  • Laporan dilihat per periode/bulan.
  • Data keuangan milik akun pribadi pengguna.

07 · UML

Class Diagram

Model data DompetKu: User memiliki Account, Account mencatat Transaction yang termasuk dalam Category; User juga mengelola Budget dan membuat MonthlyReport.

User

  • - userId: String
  • - email: String
  • + login(): Boolean
  • + logout(): Void

Account

  • - accountId: String
  • - namaAkun: String
  • - saldo: Decimal
  • + hitungSaldo(): Decimal

Transaction

  • - transactionId: String
  • - tanggal: Date
  • - jumlah: Decimal
  • - tipe: String
  • - catatan: String
  • + tambah() / ubah() / hapus()

Category

  • - categoryId: String
  • - namaKategori: String
  • - warna: String
  • + daftarTransaksi(): List

Budget

  • - budgetId: String
  • - period: String
  • - batasAnggaran: Decimal
  • + hitungSisa(): Decimal

MonthlyReport

  • - reportId: String
  • - bulan: String
  • - totalPemasukan: Decimal
  • - totalPengeluaran: Decimal
  • + generateReport(): Void

10 · Hasil

Fitur yang Sudah Berjalan

Aplikasi sudah dapat dijalankan dengan dua role (User & Admin). Menu sidebar menyesuaikan role yang login, dan data disimpan di localStorage browser.

U

User

  • Registrasi & login dengan validasi (e-mail, password min. 6 karakter)
  • Lupa sandi lewat popup atur ulang password
  • Dashboard: saldo, pemasukan, pengeluaran, grafik 6 bulan, transaksi terbaru
  • Tambah, ubah, hapus & filter transaksi
  • Atur kategori pribadi
  • Laporan per bulan, cetak & unduh CSV
  • Ubah profil & logout
A

Admin

  • Dashboard admin (ringkasan sistem)
  • Kelola pengguna: ubah data, reset password, hapus akun
  • Kelola kategori (kategori global & milik pengguna)
  • Hapus data transaksi / seluruh data pengguna

Data setiap user terpisah: user hanya melihat transaksi miliknya sendiri.
